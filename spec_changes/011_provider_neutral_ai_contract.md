# Specification Change 011 — Provider-Neutral AI Processing Contract

## Summary

VoiceFlow now separates shared AI-processing behavior from the Claude transport. Claude remains the only active provider, but the request, prompt, context, model, and response contracts are reusable for ChatGPT/OpenAI and other providers later.

## Shared request contract

`AIProcessingRequest` contains:

- The text to process.
- The processing mode: `command` or `grammarFix`.
- The selected provider-specific model ID.
- Optional `AIScreenContext`.
- A system prompt generated by `AIPromptBuilder` for the selected mode.

`AIProviderClient` is the provider boundary. A provider receives the same request contract and API key, returns final injection-ready text, and owns only provider-specific request encoding, authentication, response decoding, and model transport.

## Shared behavior

All active providers are expected to support the same product-level rules:

1. Local transcription happens before AI processing.
2. A configured leading AI prefix is detected before Grammar Fix.
3. AI command mode receives only the text after the prefix.
4. Grammar Fix is opt-in and applies only when no AI prefix matches.
5. Responses contain only the final content intended for direct text injection.
6. The selected provider model is persisted independently from other providers.
7. Optional screen context is supplied only through an explicit privacy-reviewed context provider.

The current app does not capture screen content. `AIScreenContext` is an extension slot for a future implementation rather than a claim that screenshots are currently collected or transmitted.

## Claude-first implementation

`ClaudeAIProviderClient` adapts the shared request to Anthropic’s Messages API. It uses the selected Claude model, Keychain-stored user key, compact command/Grammar Fix prompt, optional context summary, and text-only response parsing. Claude remains the only operational provider; ChatGPT remains future UI and has no active key, model catalog, or network request.

## Prompt strategy

`AIPromptBuilder` owns compact reusable prompt modes. The command prompt requests only final paste-ready content while preserving intent and valid formatting. The Grammar Fix prompt limits Claude to grammar, spelling, capitalization, punctuation, and obvious transcription corrections and forbids explanations, rewriting, Markdown, quotes, or added content.

## Security and verification

Provider adapters must never log API keys, input text, system prompts, output text, audio, or injected text. Automated tests use fake transports and verify command mode, Grammar Fix mode, model propagation, screen-context propagation, and provider-neutral client injection without making live provider requests.
